# Kindle Server

Локальный сервер-прослойка для Kindle Paperwhite 1: библиотека книг,
AI-чат через OpenRouter, прокси-упрощатель современных сайтов.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env   # впиши свой OPENROUTER_API_KEY
```

Экспортируй переменные окружения перед запуском (или используй
`python-dotenv`, если добавишь его сам):

```bash
export OPENROUTER_API_KEY=sk-or-...
export OPENROUTER_MODEL=openrouter/auto   # опционально
```

## Запуск

Есть два варианта.

**Только HTTP** (просто, без HTTPS):
```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

**HTTP + HTTPS одновременно** (Kindle получает простой e-ink дизайн по
HTTP, телефон/ноутбук — современный по HTTPS):
```bash
python generate_cert.py
python run.py
```
Это самоподписанный сертификат — при первом заходе по HTTPS браузер
покажет предупреждение "соединение не защищено", жми "продолжить"
(Advanced -> Proceed). Kindle по HTTPS не ходит вообще, так что его это
не касается.

По умолчанию: HTTP на 8000, HTTPS на 8443. Меняются через `HTTP_PORT`,
`HTTPS_PORT`, `KINDLE_TLS_CERT`, `KINDLE_TLS_KEY` в `.env`.

⚠️ Пути к сертификату **специально** не называются `SSL_CERT_FILE` /
`SSL_KEY_FILE` — это широко используемые системные переменные (через
них Python/pip/requests узнают путь к доверенному CA-бандлу). Если бы
мы переиспользовали это имя, на системах, где `SSL_CERT_FILE` уже
выставлена (нередко на Fedora и не только), сервер вместо своего
`certs/cert.pem` подхватил бы системный CA-бандл и упал бы с ошибкой
несовпадения ключа и сертификата. Проверь на всякий случай:
```bash
echo $SSL_CERT_FILE
```
Если там что-то есть — это нормально, наш сервер эту переменную не
трогает.

На Kindle открой `http://<IP_ноутбука>:8000/library`.
На телефоне/ноуте — `https://<IP_ноутбука>:8443/library` (для
современного дизайна).

## Маршруты

- `/library` — HTML-библиотека (для Kindle-браузера), загрузка книг, ссылки на конвертацию
- `/books` — JSON-список книг (для скриптов/телефона)
- `/download/{filename}` — скачать книгу
- `/upload` — POST, загрузка файла (например, с телефона)
- `/convert/{filename}?to=mobi` — конвертация через Calibre
- `/ai/` — AI-чат (обычная HTML-форма, без JS — старый Kindle-браузер это не потянет)
- `/proxy/?url=https://...` — упрощает страницу до плоского HTML

## Windows: отличия от Linux-инструкций

Код кросс-платформенный (пути через `pathlib`, сертификат — чистый
Python), но пара команд отличается.

**Виртуальное окружение и установка** (PowerShell):
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
```
Если PowerShell ругается на политику выполнения скриптов при активации —
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` разово решает.

**Переменные окружения** — `export` работает только в bash, в PowerShell:
```powershell
$env:OPENROUTER_API_KEY = "sk-or-..."
```
в cmd.exe:
```cmd
set OPENROUTER_API_KEY=sk-or-...
```
Раз переменных много (лимиты, ключ, порты) — проще поставить
`pip install python-dotenv` и в начале `main.py`/`run.py` добавить
`from dotenv import load_dotenv; load_dotenv()`, тогда всё читается
из `.env` само, без ручного `set` каждой переменной при каждом запуске.

**Calibre** — тут Windows проще Fedora: просто установщик с
[calibre-ebook.com](https://calibre-ebook.com/download_windows), он сам
кладёт `ebook-convert.exe` в PATH. Никаких танцев с зависимостями.

**Файрвол** — при первом запуске Windows Defender Firewall спросит
разрешение для Python при входящих подключениях (нужно для доступа с
телефона/Kindle по локальной сети) — подтверди для приватных сетей.

**Сертификат** — `openssl` на Windows по умолчанию не установлен,
поэтому используй `python generate_cert.py` (чистый Python, без внешних
зависимостей от системы), а не команду `openssl req` из примеров выше.

## Конвертация книг: про Calibre и лёгкие альтернативы (Linux/Fedora)

`/convert` дёргает `ebook-convert` из Calibre через `subprocess`.
Если `ebook-convert` не найден в PATH — вернётся понятная ошибка 500.

**Если `sudo dnf install calibre` тянет слишком много (Fedora подтягивает
до Calibre большой хвост Qt/зависимостей):**

1. Попробуй сначала урезанную установку — часто именно "рекомендованные"
   пакеты и раздувают размер:
   ```bash
   sudo dnf install --setopt=install_weak_deps=False calibre
   ```

2. Официальный self-contained инсталлятор Calibre — качает только то,
   что реально нужно движку конвертации, минуя репозитории Fedora:
   ```bash
   sudo -v && wget -nv -O- https://download.calibre-ebook.com/linux-installer.sh | sudo sh /dev/stdin
   ```
   Можно и без `sudo` — тогда поставится в домашнюю папку.

3. **KindleGen** — официальный (ныне не поддерживаемый Amazon) отдельный
   бинарник для конвертации epub/html → mobi, без всех зависимостей
   Calibre (десяток мегабайт, никакой установки — просто исполняемый
   файл). Подходит, если тебе не нужна вся Calibre, а нужен именно
   epub/html → mobi. Официально Amazon его снял с раздачи, так что
   ищи через архивы — на легитимность старых зеркал я гарантий дать
   не могу, проверяй сам.

Учти также: PW1 нативно читает **TXT, PDF, MOBI, AZW** без всякой
конвертации — если книга уже в одном из этих форматов, `/convert`
вообще не нужен.

## Замечания по безопасности

- `/download` и `/convert` защищены от path traversal (резолвинг пути
  внутри `books/`).
- Авторизации всё ещё нет — сервер рассчитан на локальную сеть. Не
  выставляй порты наружу в интернет без доп. защиты (хотя бы basic
  auth через nginx/Caddy перед сервером).
- HTTPS через самоподписанный сертификат защищает канал (шифрование),
  но не проверяет "подлинность" сервера для браузера — это ожидаемо
  для локальной сети, не для продакшена.

## AI: таблицы и формулы

AI-ответы форматируются **на сервере**, а не через MathJax/KaTeX: это важно
для старого WebKit Kindle Paperwhite 1.

- Markdown-таблицы превращаются в обычный HTML `<table>`.
- `$$...$$` и `\[...\]` превращаются в читаемый блок формулы.
- `$...$` и `\(...\)` превращаются в inline-формулу.
- Частые LaTeX-команды (`\text{}`, `\frac`, `\cdot`, `^`, `_`, греческие
  буквы и т. п.) преобразуются в HTML/Unicode.
- HTML из ответа AI предварительно экранируется, поэтому ответ не может
  вставить произвольный HTML/JS.
- MathJax и KaTeX специально не используются: старый Kindle не должен
  загружать тяжёлый JavaScript для рендера формул.

После обновления установи новую зависимость:
```bash
pip install -r requirements.txt
```
